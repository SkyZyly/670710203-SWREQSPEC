# แผนทางเทคนิค: จองคิวตรวจสุขภาพ (Booking)

## 1. สรุปแนวทาง

ฟีเจอร์นี้ให้ผู้รับบริการที่ยืนยันตัวตนแล้วเลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพเพื่อรับหมายเลขคิว (FR-BKG-01, FR-BKG-04)
ระบบจะแสดงช่วงเวลาว่างและจำนวนที่นั่งคงเหลือภายใน 30 วันข้างหน้า (FR-BKG-01)
ระบบตรวจสอบคิวเดิมในวันเดียวกันและป้องกันการจองซ้ำ (FR-BKG-02)
การยืนยันการจองต้องป้องกันกรณีช่วงเวลาเต็มระหว่างการยืนยัน และไม่สร้างรายการจองซ้อน (FR-BKG-03)
การบันทึกการจองและการส่งข้อความแยกกัน โดยการส่งข้อความทำงานแบบ asynchronous และมีคิวส่งซ้ำ (FR-BKG-04, FR-BKG-05, IF-NOT-01)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| MySQL | CON-TECH-01 | ฐานข้อมูลหลักของระบบ |
| React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | หน้าบ้านสำหรับเลือกแพ็กเกจ วัน และช่วงเวลา |
| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | หลังบ้านสำหรับ API การค้นหาและการจอง |
| TLS 1.2 ขึ้นไป | NFR-SEC-01 | ใช้กับการรับส่งข้อมูลการจอง |
| Asia/Bangkok | ASM-02 | ใช้คำนวณวันเดียวกัน |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `Booking` | `id`, `hn`, `package_id`, `slot_id`, `booking_date`, `queue_number`, `status`, `created_at` | FR-BKG-02, FR-BKG-04, FR-BKG-05 |
| `TimeSlot` | `id`, `package_id`, `slot_date`, `start_time`, `end_time`, `capacity`, `remaining_seats` | FR-BKG-01, FR-BKG-03, FR-BKG-06, ASM-01 |
| `Package` | `id`, `name`, `active` | FR-BKG-06 |
| `NotificationJob` | `id`, `booking_id`, `channel`, `status`, `attempt_count`, `next_attempt_at`, `last_error` | FR-BKG-04, FR-BKG-05, NFR-REL-02, ASM-03, IF-NOT-01 |
| `AuditLog` | `id`, `accessor`, `accessed_at`, `hn`, `resource` | DOM-PDPA-01, AC-BKG-06 |

`Booking` ใช้ `hn` เป็นข้อมูลอ้างอิงผู้รับบริการ และไม่มีฟิลด์เลขบัตรประชาชนตาม IF-HIS-01
ข้อมูลเลขบัตรประชาชนใช้ค้นผ่าน HIS เท่านั้น และไม่เก็บในตารางการจอง (IF-HIS-01)
การสร้าง `Booking` และลด `remaining_seats` ต้องตรวจสอบที่นั่งพร้อมกันเพื่อรองรับ FR-BKG-03 และ AC-BKG-03
รูปแบบการกำหนด `queue_number` ยังไม่กำหนดจนกว่าจะตอบ Q-02 (Q-02)

## 4. API / หน้าจอ

- `GET /booking/availability` รับ `package_id`, ช่วงวันที่ และเขตเวลา; คืนวัน ช่วงเวลา และจำนวนที่นั่งคงเหลือ (FR-BKG-01, FR-BKG-06)
- หน้าจอเลือกแพ็กเกจ วัน และช่วงเวลา; เมื่อเปลี่ยนแพ็กเกจให้โหลดช่วงเวลาว่างใหม่ (FR-BKG-06)
- `POST /booking` รับ `package_id`, `slot_id`, และข้อมูลยืนยันตัวตน; คืน `booking_id`, `queue_number`, และสถานะการจอง (FR-BKG-02, FR-BKG-04)
- `POST /booking/confirm` ตรวจสอบคิวเดิมและที่นั่งก่อนบันทึก; คืนหมายเลขคิวเดิมเมื่อปฏิเสธ หรือแจ้งช่วงเวลาเต็มพร้อมตัวเลือกใกล้เคียง 3 รายการโดยรวมวันถัดไป (FR-BKG-02, FR-BKG-03)
- `GET /booking/{booking_id}` คืนรายละเอียดการจองและหมายเลขคิว พร้อมบันทึก audit log เมื่อเข้าถึงข้อมูลผู้รับบริการ (DOM-PDPA-01, AC-BKG-06)
- Worker ส่ง `NotificationJob` แบบ asynchronous และส่งซ้ำภายใน 5 นาทีตามจำนวนสูงสุด 3 ครั้ง; การจองไม่รอผลการส่งข้อความ (IF-NOT-01, NFR-REL-02, ASM-03)
- ทุก endpoint ที่เข้าถึงข้อมูลผู้รับบริการต้องตรวจผลยืนยันตัวตนจาก IDP ก่อน (IF-IDP-01)
- การค้นหาข้อมูลผู้รับบริการใช้เลขบัตรประชาชนผ่าน HIS และนำ HN มาใช้งานภายในระบบ (IF-HIS-01)

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| CON-TECH-01 | ใช้ MySQL ในโมเดล `Booking`, `TimeSlot`, `NotificationJob` และ `AuditLog` | ใช้แล้ว |
| DOM-PDPA-01 | Entity `AuditLog` และ `GET /booking/{booking_id}`; เก็บ log อย่างน้อย 1 ปี | ใช้แล้ว |
| IF-IDP-01 | ตรวจผลยืนยันตัวตนก่อนทุก endpoint ที่เข้าถึงข้อมูลผู้รับบริการ | ใช้แล้ว |
| IF-HIS-01 | ค้นผ่าน HIS ด้วยเลขบัตรประชาชน ใช้ HN ภายใน และไม่เก็บเลขบัตรประชาชนใน `Booking` | ใช้แล้ว |
| IF-NOT-01 | `NotificationJob` และ worker แบบ asynchronous ไม่รอผลส่งข้อความ | ใช้แล้ว |

## 7. ลำดับงาน

1. กำหนด schema MySQL สำหรับ `Booking`, `TimeSlot`, `Package`, `NotificationJob` และ `AuditLog` โดยไม่เก็บเลขบัตรประชาชนใน `Booking` (CON-TECH-01, IF-HIS-01, DOM-PDPA-01)
2. เชื่อมการตรวจผลยืนยันตัวตนจาก IDP และการค้น HN จาก HIS ก่อนเข้าถึงข้อมูลผู้รับบริการ (IF-IDP-01, IF-HIS-01)
3. สร้าง API และหน้าจอค้นหาช่วงเวลาว่างภายใน 30 วัน พร้อมจำนวนที่นั่งคงเหลือ (FR-BKG-01, FR-BKG-06)
4. สร้างการตรวจสอบคิวเดิมในวันเดียวกันและการคืนหมายเลขคิวเดิมเมื่อปฏิเสธ (FR-BKG-02, AC-BKG-02)
5. สร้างการยืนยันการจองแบบตรวจสอบที่นั่งและบันทึกการจองร่วมกัน เพื่อป้องกันรายการจองซ้อน (FR-BKG-03, FR-BKG-04, AC-BKG-01, AC-BKG-03)
6. สร้าง `NotificationJob` และ worker แบบ asynchronous พร้อมการส่งซ้ำสูงสุด 3 ครั้งภายใน 5 นาที (FR-BKG-05, NFR-REL-02, IF-NOT-01, ASM-03, AC-BKG-04)
7. เพิ่ม audit log สำหรับการเข้าถึงข้อมูลการจอง และตั้ง retention ไม่น้อยกว่า 1 ปี (DOM-PDPA-01, AC-BKG-06)
8. ทดสอบ performance ที่ผู้ใช้พร้อมกัน 200 คนและตรวจ p95 ตามเกณฑ์ (NFR-PERF-01, AC-BKG-05)
9. ทดสอบ usability กับผู้ใช้ใหม่ 10 คนตามเกณฑ์สำเร็จ 8 ใน 10 คน (NFR-USE-01)
